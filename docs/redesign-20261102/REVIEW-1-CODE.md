## 評価の範囲

## 結論

コードと掲載内容から直ちに断定できる新規P0は見つからなかった。架空顧客・導入自治体・受賞歴・ユーザー数・精度／成長率・売上実績の追加は見当たらない。スポーツDXテーマは想定例と明示され、アプリ画面のスコアを分析精度と誤認させない注記がある。新規ページの住所は三鷹市までで、旧オフィスの町名・番地や個人の自宅詳細は含まない。下記P1を直し、ブラウザで残る不確実性を解消することを勧める。

## P1指摘と修正案

### R1. 事例3枚目を説明に合う実UIにする

- 対象：`app/cases/ai-sports-trainer/content.tsx` の `03 次の練習につなぐ`。
- 現状：画像は `pitching-score.webp`（スコア／レーダーチャート）だが、説明は練習メニュー・履歴まで含む。
- 観察：既存 `public/images/cases/03-training.png` は「AIドリル提案」の実画面で、3候補、ドリル名、理由、所要時間、詳細ボタンがある。
- 推奨：3枚目を既存training画像に置換し、altと説明を「分析をもとにしたドリル提案」へ揃える。履歴が写っていない画像で履歴を証拠として主張しない。
- 検証：モバイル／Desktopの実画面で画像・見出し・説明の一致を確認。

### R2. ケースの実UIをモバイルで読み取れる大きさにする

- 対象：`app/globals.css` の `.screen-stage` / `.screen-stage img`。
- 現状：600px以下で正方形ステージに26px余白、画像はheight 100%、portrait（約1:2.16）をcontain。375px viewportなら縦に合わせた画像幅が約130pxになる可能性がある。
- この寸法はCSSからの推定であり、実DOMで計測済みの値ではない。
- 推奨：モバイルではportrait向けステージ（例：aspect-ratio 3/4〜3/5）を使い、横幅と高さの上限を見直す。画像拡大を追加するより、まず本文中で十分な大きさを確保する。
- 検証：390pxスクリーンショットで、AIドリルのタイトルや主要ラベルが読めるかを確認。単なる端末シルエットになっていないこと。

### R3. フォームの流入元を許可値で区別する

- 対象：`app/page.tsx` の `<ContactForm source="home" />` と各下層CTA。
- 現状：`/?service=sports-dx#contact` などテーマは渡せるが、フォーム開始・成功のsourceは常にhome。CTAのlocation自体は送られるので、クリックイベントの分解は可能。
- 推奨：必要なら `from=sports_dx / case_study / security` など固定値のqueryを受け、許可リストに合うものだけsourceにする。生URL・referrer・入力内容を送らない。あるいは現状の計測限界を仕様に明示して公開後の計測設計に残す。
- 検証：下層CTA→フォーム開始→stub成功のsource、page、serviceの固定値を確認。

### R4. 一時転送物と品質ゲートを整理する

- 対象：`public/images/product/*.b64`、`docs/.../before/*.b64`、`next.config.mjs`。
- 現状：実装用のbase64転送ファイルがpublic配下にも残っており、そのままでは静的配信対象。型／lint無視は既存configを踏襲。
- 推奨：一時転送物を本番アセット／最終PRから除外。既存configを維持する場合も独立した `tsc --noEmit` 等の結果を保存し、build成功と型検証成功を分ける。
- 留意：画像の本体ファイルを消さない。baselineの旧所在地は変更前の証拠としてのみ扱い、現行ページの所在地と混同しない。

## 重大度を上げずに明示すべき未検証

- 実端末・実ブラウザでの横スクロール、重なり、タップ／キーボード／スクリーンリーダー操作、コントラストの実コンテキスト。
- 見込み客の5〜10秒理解度、実CVR、商談率。AIレビューで代替した実測値を作らない。
- スポーツアプリの既存データ取扱いは既存文章／ソースの確認コメントを維持したもので、本レビューでは本番バックエンドを再検証していない。
- GA4が未接続ならイベントの実受信は未確認。将来の自動page_view／拡張計測のPII除外は別に必要。
- APIのOrigin確認／honeypotは実装済みだが、Cloudflareレート制限／Turnstileは未設定。これはフォーム担当ドキュメントにも記載済み。
- 生の秘密値を出力しないファイル名検索では、新規app/components/lib/functions/public/docsテキストからwebhook URL・API secret形式は検出されなかった。これは完全なsecret scannerを実行した結果ではない。
