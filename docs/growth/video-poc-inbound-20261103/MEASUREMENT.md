# AI動画解析・PoC受託開発：計測と営業効果の確認

## 目的と評価指標

最重要指標は有効な法人・団体開発相談、商談、提案、有償PoC、開発受注、受注金額です。PVやSEO順位は診断指標であり、成約率の代理として扱いません。自社アプリのサブスクリプション売上とは分けます。

| 段階 | 指標 | 確認方法 |
| --- | --- | --- |
| 検索流入 | `/ai-video-analysis`の自然検索セッション、流入クエリ | GSC・GA4（データ取得可能時のみ） |
| 関心 | 対象LP閲覧、`cta_click`、`case_study_click` | GA4（測定IDを正しく設定した後） |
| 受付 | `contact_form_start`、`contact_form_submit`、`contact_form_success`、`contact_form_error` | フォームイベントとCloudflareの受付を区別 |
| 有効問い合わせ | `video_poc`を出所とする、業務用途が具体的なBtoB開発相談 | Slack受信／営業記録 |
| 商談・受注 | 面談、提案、有償PoC、開発契約、売上・入金 | 営業記録（ユーザーの承認なしに送信しない） |

## 有効問い合わせの基準

発注権限または発注意向を持つ事業者・団体が、具体的な開発用途や検証したい結果を提示し、次のアクションに進める相談。個人向けアプリの質問、勧誘、スパム、一般的な情報照会は別に扱います。

## 実装時のデータ制約

- LPは`page=video_poc`、相談元も`source=video_poc`に固定。元URLやメール、氏名、相談本文をGA4に送信しない。
- 自社アプリ事例リンクは`case_study_click`で計測するが、外部顧客の導入実績としては数えない。
- GA4の実測定IDとCloudflare Pages環境設定は未確認。送信処理の実装だけでGA4受信を「済み」とはしない。
- 実際のSlack通知とGoogle Analytics受信を別々に確認する。

## 公開後の測定

T0は最新LPが本番で閲覧できることを確認した日時。PR作成・マージをT0にしない。

- **T0＋7日**：公開URL、indexability、実フォーム受付、GA4のページビュー・CTA・送信イベント、主要既存導線が成立するかを確認。
- **T0＋28日**：実際の有効問い合わせ、面談化率、提案化率、有償受注の件数と金額を評価。
- 計測欠測は「0件」と読み替えない。小サンプルで成果を断定しない。

受託開発向けSEO記事は別PR #5で管理し、同じ開発発注者向けのコンテンツをCyber Knockの`/insights/`に集約します。AIスポーツトレーナーの競技コラムにはコピーしません。
