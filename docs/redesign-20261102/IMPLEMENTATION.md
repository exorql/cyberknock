## 2. デザインと実績の根拠

採用コンセプトは「動きから、事業へ。」。紙色・墨色・teal、観測枠、反復する線、明瞭な日本語見出しを共通の表現にした。実アプリ画面と、開発・実証の判断を示す概念図を区別している。

- `ProductVisual`: 実アプリの投球フィードバックと評価画面。画像とcaptionの領域を分け、端末画像で実績名を隠さない。
- `DecisionLoop`: 映像条件、AIの判断範囲、利用体験、運用の見直しを実UIに関連づける。線は計測データではないと明記。
- `PilotBlueprint`: 実証で揃える問い、現場で確認すること、次の判断と想定成果物を示す。導入済み案件や成功実績の図ではない。
- 実績数値、受託顧客ロゴ、従業員、受賞歴、推薦文は追加していない。アプリ内のスコアは表示例であり、分析精度を証明する数値として扱わない。
- 既存サイトの公開素材と、実アプリの提供素材を使用。WebP化・サイズ違いの生成は配信最適化のためで、人物・結果・画面内容を生成していない。

コンセプト3案と受賞サイト4件／BtoBサイト4件の比較は[BENCHMARKS.md](BENCHMARKS.md)。受賞歴の公式確認と、未測定のCVR・モバイル・性能を明確に分けている。

## 4. コードと依存

Next.js 15.5.28、React 19.2.6、TypeScript、Tailwind、静的export、Cloudflare Pages Functionsという既存構成を維持。新しい本番用ライブラリは追加していない。

- 本文はServer Component主体。メニュー、フォーム、イベント計測だけをclientへ限定。
- `functions/contact.js`は既存の`SLACK_WEBHOOK_URL`を使う構造を維持し、未設定・上流失敗時に成功を偽装しない。
- `typescript.ignoreBuildErrors`を除去し、型エラーをbuildの合否に反映。
- 未使用の`components/ui`を削除せず、現在の公開ページで使うコンポーネントだけをTailwind走査対象にした。将来UI部品を使用する場合の設定はREADMEに記載。
- SEOのcanonical、sitemap、robots、Search Console verification、既存の構造化データを維持・整合。新しい実績評価値やreview schemaは作っていない。

再現手順は[README](../../README.md)。品質ゲートは`npm run check`。CIは日本語フォントを必須確認し、主要5ページをLighthouse 12.8.2で監査する。

## 6. 実装した計測と外部条件

許可した9イベントと固定語彙だけを既存`window.gtag`へ渡す。フォーム本文・氏名・メールアドレス・任意のURL query/hashを送らない。GA4 IDや既存トラフィック・商談データは取得できていないため、現在は計測を接続済みとは判定しない。

イベント定義、CRMの有効相談／商談／案件化／受注、分母、重複排除、観測期間、5名の理解度テストは[MEASUREMENT-PLAN.md](MEASUREMENT-PLAN.md)にまとめた。

本番リリース前に残る確認は、通知先への実到達、実機・支援技術、ユーザーの公開承認。公開後に確認する項目はGA4接続、実ユーザーCWV、理解度、有効問い合わせと営業成果である。90点の主観評価や受賞を、これらの実績の代わりにしない。
