## 目的と完成条件

既存のデザイン採点は主要5ページで **78.75〜82.25 / 100**。主な未達項目は「造形と独創性」「実績・専門性を示す具体的な根拠」「問い合わせ導線の文脈」である。Awwwards / Webby Awards / FWAに評価される独自性と技術的完成度を目指す。ただし、**賞の受賞可能性、100点満点の90点、問い合わせCVRの向上を実証できていない段階で合格としない**。

## 制作・レビューの反復（3サイクル）

### Cycle 1 — 第一印象と独自性

- ホームの第一画面を濃いインクグリーンに切り替え、実アプリの公開UIと立体的な構図を主役にした。確認できない実績数や架空の顧客ロゴは追加していない。
- 英字の細いキッカー、余白と大型の和文見出し、測定枠に通じる細い軌道線、限定的なライム色を共通の言語に統一。
- 第一回スクリーンショット確認で、淡色の実アプリカードに継承された白いテキストを検出。表示色を修正し、再撮影した。

### Cycle 2 — 「何ができるか」から「どう判断するか」へ

- ホームの汎用的な説明文を、見せる判断「FIELD NOTES」へ転換。実際のプロダクト設計判断を3項目に分解。ネイティブ `details` を使い、開閉に必要な追加JavaScriptは不要。
- 事例章は濃い背景で実画面・設計プロセス・公開先の対比を強化。スポーツDXは別トーンの実証プラン表現で、トップの繰り返しを避ける。
- サービス一覧、費用・開発工程、問い合わせ、文書の読みやすさにもブランドの共通デザイントークンを適用。
- 390px幅の本文が不自然な短い行で終わる問題を発見しコピーを短縮した。

### Cycle 3 — 回遊・モバイルの磨き込み

- 長いケーススタディとDXページに「実画面／担当範囲／AI品質／相談先」などの章ナビゲーションを追加。
- モバイルでは横スクロール可能であることをラベルで明示。相談リンクのイベントは許可値のみ、個人情報やraw URLを送らない。
- キーボード・画面幅・lazy image読み込み、コントラスト、reduce-motion、forced-colorsを確認。実際の送信先に問い合わせテストは送らない。
