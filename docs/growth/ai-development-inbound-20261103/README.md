# Cyber Knock｜AI・プロダクト開発の総合受託LP

更新日：2026年11月3日。対象：`exorql/cyberknock` PR #4。最終目標は**有効な法人の受託開発相談 → 商談 → 提案 → 有償契約・売上**。PV・デザイン品質・検索順位は手段。

## ポジショニング

- **Cyber Knock公式トップ `/`**：事業全体と自社プロダクト経験を紹介。AI・Web・モバイル開発の総合窓口。
- **総合受託LP `/ai-development`**：AI機能開発、PoC、Web・モバイルアプリの開発相談。H1は「AI・プロダクト開発を、構想から実装まで。」。
- **`/ai-video-analysis`**：現在は公開しない。動画解析は総合LPのサービス例に含める。専門LPを追加する場合は日本向け検索需要・競合・既存CVRを調べて判断し、重複させない。
- **`/insights/`**：PR #5の開発発注者向けSEO記事をCyber Knockに掲載。AIスポーツトレーナー `/columns/`（アプリ利用者向け）にコピーしない。

## 新LPの価値訴求

1. 課題と対象利用者から、何を開発するべきか整理できる。
2. 既知の技術なら実装、未知の精度や連携が問題なら必要部分だけPoCを行う。
3. Web・モバイル・API・AIを一体のプロダクトとして開発できる範囲を相談できる。
4. 自社アプリ「AIスポーツトレーナー」の開発と運用経験を、実績として確認できる。第三者への商用導入実績ではない。
5. 予算・納期が未確定でも問い合わせでき、初回に機密ファイルを要求しない。

SEO title、description、canonical、OGP、FAQ/Service構造化データ、サイトマップ、ヘッダー／フッター／スポーツDXの導線は`/ai-development`へ統一。受託窓口のsourceは`ai_development`に変更し、もとのSlack Webhook宛先を維持する。

## 誤認・権利リスクを防ぐ

- 契約前の顧客案件やその技術検証内容、非公開映像・写真・UI・相手先のロゴ・名前を掲載しない。
- AI機能の精度、将来の受注・収益、固定価格・納期を根拠なしに約束しない。
- 動画解析を「実績がある顧客向け受託開発」として扱わず、対応候補の技術カテゴリにとどめる。
- 公開済みの自社アプリのストア導線、個人向けの競技コラムを壊さない。
- GitHubの途中コミットには以前の個別案件公開案が残るため、PR #4は公開用mainに**Squash and merge**で最終内容のみ取り込む。古いPRやプレビューへのアクセスが自動消去されるものではない。
