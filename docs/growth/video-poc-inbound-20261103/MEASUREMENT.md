# AI動画解析・PoC受託開発：事業効果の計測契約

## 分析対象と目的

T0はCyber Knock新ページが本番で確認できた日時。マージ時刻やPR作成時刻をT0としない。

| 分析層 | 指標 | 判定 |
| --- | --- | --- |
| 流入 | `/ai-video-analysis` と2事例ページの自然検索着地セッション、主要検索クエリ、参照元 | 診断指標。ゼロ流入と計測欠測を混同しない |
| 興味 | `case_study_view`、`case_study_click`、`cta_click` | 技術事例からの相談検討を把握 |
| 受付 | `contact_form_start`、`contact_form_submit`、`contact_form_success`、`contact_form_error` | GA4と実Slack受信の突合せ。イベント受信≠契約 |
| リード品質 | `video_poc`・`soccer_poc`・`kyudo_poc` 別の実問い合わせ | 事業者、対象動画／用途、予算／期限、次のアクションの有無 |
| 営業成果 | 有効問い合わせ → 実面談 → 提案 → 有償PoC／開発契約 → 請求・入金 | 最終KPI。金額が確定していなければ未確定とする |

## 有効問い合わせの基準

企業・団体、もしくは開発の発注権限／発注意向を持つ方からの具体的なAI動画解析・開発相談。対象用途や検証したいことが明確で、営業上の次のアクションが取れるもの。個人アプリの使い方質問、勧誘、スパム、無関係な一般質問は別に数える。個人の氏名やメールをGA4に送信しない。

## ソース・イベント

- 専用LP：`page=video_poc` `source=video_poc`
- サッカー検証：`page=soccer_poc` `source=soccer_poc`
- 弓道検証：`page=kyudo_poc` `source=kyudo_poc`
- サービスは既存の `service=sports-ai` を使用。新しい広告用トラッカーや外部スクリプトは追加しない。
- アナリティクスの `page_location` は登録済み固定URLだけを送信し、フォーム入力値・生検索パラメータ・参照元URLを送信しない。
- Cloudflareの受信成功とSlack配送を別に確認する。GA4のイベント受付は本番で未検証。

## 7日・28日の評価

- **T0＋7日**：3URLの正常表示とGSC登録状況、3sourceの計測と受付、入力エラー率と実送信成功、元サイトの重要CTAの維持。
- **T0＋28日**：有効問い合わせ数、商談化率、提案率、有償案件件数・金額。発注額が未確定なら勝手に計上しない。
- 数週間の小サンプルで売上の因果を断定しない。まず営業履歴（手動でも可）と流入・CTA・送信の欠測を減らす。

## 施策を継続する判断

新LPが発注意欲のある検索流入を獲得しているか、フォームまで到達するか、有効問い合わせへつながるかを順に調べる。流入が増えても営業対象外の質問しか増えなければ、発注意図をより強く打ち出す。技術検証の内容が足りず問い合わせに至らない場合は、公開許諾のとれた実デモ・再現性のある計測条件・顧客の承認済み事例を優先する。
